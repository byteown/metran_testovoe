# Папка тестового задания (выдаётся кандидату)

- `TASK.md` — текст задания (база 4–6 ч + зачётный минимум + бонусы по желанию)
- `data/` — данные для задания: пример выгрузки из 1С (эталоны есть)
- `docs/` — регламенты финансовой службы (источник для RAG)
- `scripts/` — служебные скрипты; в комплект для кандидата не входят

## Источник данных

`data/` — единственный источник для задания. Никакие внешние выгрузки делать не нужно:
данные согласованы, эталонные ответы существуют, проверка объективна.

## Состав данных (`data/`)

| Файл | Содержимое |
|---|---|
| `counterparties.csv` | 18 контрагентов: имя, ИНН, тип (buyer/supplier/both), регион, менеджер |
| `invoices_issued.csv` | 26 счетов покупателям (реализация): сумма, срок оплаты, статус (paid/pending/overdue), оплачено |
| `invoices_received.csv` | 16 счетов от поставщиков: сумма, срок оплаты, статус, оплачено |
| `payments.csv` | 27 платежей: дата, контрагент, сумма, назначение (связь со счётом) |
| `account_balances.csv` | ОСВ по счетам: 51, 50, 60.01, 62.01, 68.02, 90.01.1, 91.02 (сальдо нач./обороты/сальдо кон.) |
| `receivables.csv` | Развёрнутая дебиторка (14 позиций): контрагент, договор, счёт, сумма, дата, просрочка дней, статус (current/overdue) |

Связи между файлами: `invoices_issued` ↔ `payments` (назначение «Оплата по счёту СБ-XXXXX»);
`receivables` = остатки по неоплаченным счетам; `account_balances` (62.01) сходится
с суммой `receivables`. Данные согласованы и перепроверены.

Статус счёта (`paid`/`pending`/`overdue`) определяется от даты срока оплаты на отчётную
дату 31.07.2026: оплачен полностью — `paid`; срок ещё не наступил — `pending`; срок
истёк — `overdue` (возможна частичная оплата). При расчёте просрочки ориентируйтесь
на `receivables.csv` (поля `status` + `overdue_days`).
